# ブラウザ実機確認ガイド

Vitest / Jest だけでは検出できない CSS レイアウト、実描画、ユーザー操作フローはブラウザで確認する。
Codex では Browser プラグイン、Claude Code では Playwright MCP など、その環境で利用できるブラウザ操作ツールを使う。

## 使う場面

- 単体テストは通るが画面上の挙動が直っていない
- CSS、flex、フォントメトリクス、スクロール、レスポンシブ表示が絡む
- Quill、Highlight.js、`dangerouslySetInnerHTML` など jsdom と実ブラウザで差が出る
- ログイン、チャネル切替、メッセージ送信など複数コンポーネントをまたぐ
- React 19 の Suspense まわりで API リクエスト数やローディング状態を確認したい

## 開発サーバー確認

既にサーバーが起動していることが多いため、重複起動する前に確認する。

```bash
lsof -i :3001 -i :5173
```

`node` が LISTEN していれば `http://localhost:5173` に接続する。
未起動の場合だけ `npm run dev` を起動する。

自分が起動したサーバーだけを終了する。ユーザーや別プロセスが起動していたサーバーは止めない。

## 確認観点

| 観点 | 確認内容 |
|---|---|
| 実描画 | 要素が見切れない、重ならない、意図した幅で表示される |
| 操作 | クリック、入力、キーボード操作が実際に動く |
| 通信 | API リクエストが想定回数に収まる |
| 状態 | ローディング、エラー、空状態、更新後表示が成立する |
| 更新反映 | dev server が最新コードを配信している |

## React 19 Suspense のリクエスト数確認

API が無限に呼ばれていないか確認する。

- 同じ `/api/` パスが数十件以上発火する場合は Suspense 境界と Promise 生成位置を疑う
- 開発環境の StrictMode では 2 回程度の発火は正常範囲
- 詳細な修正方針は `doc/react19-suspense-guide.md` を参照する

## このプロジェクトの操作メモ

- 新規ユーザーの初回ログインではオンボーディングダイアログが出るため、必要ならスキップする
- メッセージ入力は Quill の `.ql-editor` にフォーカスして確認する
- 投稿権限がないチャネルでは入力欄が無効化されるため、送信検証は権限のあるチャネルで行う
- メッセージは Quill Delta 形式で保存され、表示時に React ノードへ変換される
- 過去メッセージと新規メッセージで CSS 適用状態が異なることがあるため、両方を確認する

## 一時ファイル

ブラウザツールがスクリーンショット、ログ、snapshot ファイルを生成する場合がある。
作業完了前に `git status` で確認し、コミット対象から除外する。

削除が必要な場合は、生成ファイルの一覧を示してユーザー確認を取る。
調査根拠として残したいケースがあるため、確認なしに自動削除しない。
