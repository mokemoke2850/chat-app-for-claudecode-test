# Issue #154 — feat: チャットヘッダーのコンパクト化

> Phase 1 / 並列OK / 難易度: 低

## 概要

`ChatPage.tsx:255-288` の 3 行ヘッダー（チャンネル名 / トピック / メッセージ・ファイルタブ）を 1 行ヘッダー化し、ファイル切替をアイコンボタン化することで 50〜60px の表示領域を回復する。

## 仕様確認事項

- **アイコン化のアフォーダンス**: 「ファイル一覧切替」アイコンは `AttachFile` / `FolderOutlined` のいずれか。トグル状態の視覚化は背景色変化で十分か、別アイコンに切り替えるか。
- **トピック非表示時のレイアウト**: トピックが空のチャンネルでもアイコン群と名前は 1 行に収まる前提でよい。
- **モバイル幅対応**: 既存レイアウトでモバイル幅にどこまで配慮しているか。MVP は現状の最小幅基準で良いと想定。

## 影響範囲

### Client

- `packages/client/src/pages/ChatPage.tsx` — ヘッダー領域 (255-288 行付近) の構造変更
- `packages/client/src/components/Channel/ChannelTopicBar.tsx` — 1 行表示用の省略形バリアントを追加 or props で切替
- ファイル/メッセージのビューモード切替の state 管理: 既存タブ状態を流用し、トリガをアイコンボタンに差し替えるだけで済む見込み

### Server

- 変更なし

### DB

- 変更なし

## 並列実行時の競合警戒

- Phase 1 の他 Issue とは触るファイルが完全に分離（#146 は `UserAvatar` 周辺、#148 は `MessageInput` / サイドバー）。
- 後続フェーズ（特に #149 ゲスト閲覧 / #147 ステータス）が `ChatPage.tsx` に若干触る可能性があるため、**Phase 1 で先に main に取り込んでおく**ことで後続のリベース負担を減らす。

## 実装ポイント / 落とし穴

- **アイコンの並び順**: 既存（予約送信 / 招待 / 編集）+ 追加（ファイル切替）の順。役割が「コンテンツ作成」「メンバー管理」「設定」「ビュー切替」の順に並べると自然。
- **トピックの省略**: `textOverflow: 'ellipsis'` + `whiteSpace: 'nowrap'` + `overflow: 'hidden'` の 3 点セットを忘れない。トピックの全文ホバー表示（`title` 属性）も付ける。
- **トピック編集 UI の維持**: ホバー時の編集アイコン表示や編集ダイアログは現状維持。
- **タブから状態切替への変更**: 既存タブの ARIA や URL クエリを使っていないか確認し、変えるならトーストや fallback も合わせる。
- **テスト**: 既存 `ChannelTopicBar` テストと `ChatPage` テストが落ちないか必ず確認。

## テスト観点

- フロントエンド
  - 1 行ヘッダーにチャンネル名・トピック・アクションアイコンが収まる
  - ファイル切替アイコンクリックでファイル一覧表示、再クリックでメッセージ復帰
  - トピックが長い場合に省略表示される
  - 既存の編集ダイアログ・招待リンク・予約送信ダイアログ・ファイル一覧が正常動作
